# CareerOS evidence model

CareerOS does not use unsupported percentages to describe professional
readiness.

## Evidence states

### Demonstrated

Supported by professional experience, a working project, or public-safe proof.

### Practicing

Actively exercised through approved work, independent labs, or an active build.

### Learning

In active development without enough evidence for a mastery claim.

### Planned

Intentionally deferred until higher-leverage evidence is complete.

## Evidence levels

A capability can progress through:

1. learned
2. practiced
3. built
4. used professionally
5. produced a measured outcome
6. taught or mentored
7. designed or led

## Strong evidence examples

- working repository
- deployed application
- original project photographs or video
- reproducible lab
- tests
- architecture diagram
- sanitized case study
- public technical writing
- approved professional outcome

## Role-lens rule

A role lens may reorder and interpret evidence, but may not change the underlying
facts. Each role page must include evidence, gaps, next proof, and a truth
boundary.

## Personal-project rule

Planned subsystems must never inherit the evidence state of the entire project.
Rallye Control therefore tracks evidence by subsystem.
