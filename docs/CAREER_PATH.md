# Career path working model

This is a personal working model, not an official employer framework.

## Core identity

Customer-facing technical systems professional specializing in troubleshooting,
integrations, analytics, solution delivery, and business value.

## Current foundation

### Technical Support Engineer

Demonstrated evidence includes:

- enterprise SaaS troubleshooting
- customer issue ownership and escalation coordination
- APIs, integrations, authentication, logs, and data-flow analysis
- hands-on Linux administration across patching, network rollback, permissions,
  configuration editing, and log-based investigation
- regulated and federal environment experience
- documentation, reproduction, and technical communication

## Strong current and adjacent role lenses

- Senior Technical Support Engineer
- Technical Account Manager
- Customer Success Engineer

## Transferable secondary lens

- Data Analytics

These roles emphasize different parts of current evidence. They are not all
claimed as current titles.

## Active engineering paths

### Application Engineer

Required next evidence:

- backend code navigation
- regression tests
- reviewed pull requests
- narrow maintainable fixes
- deployment and validation
- software design and lifecycle ownership

### Software Engineer

Current positioning:

- active development path, not strongest current alignment
- React, JavaScript, TypeScript, and an existing MERN/full-stack foundation
- shipped project, API, database, testing, and deployment evidence in development
- currently pursuing a master's degree in computer science

Required next evidence:

- reviewed backend contributions
- automated testing depth
- maintainable software-design evidence
- repeatable deployment ownership
- data structures, algorithms, and computer-science depth through the master's program

## Long-term convergence

### Forward Deployed Engineer

Required combined evidence:

- customer discovery and ambiguity management
- rapid implementation
- backend and data fluency
- deployment and production debugging
- cross-functional ownership
- measurable technical and business outcomes

## Exploratory path

### Data Science

Current foundation:

- Python and SQL
- OpenCV computer-vision prototype
- analytics and data-transformation experience

Required before job-ready positioning:

- statistics and experiment design
- reproducible public datasets and notebooks
- model baselines and evaluation
- error analysis
- cross-validation
- end-to-end machine-learning case study

## Rule

Software Engineer is the explicitly approved Sprint 001 addition. Do not add
another role lens until an existing lens gains a strong new proof artifact.
