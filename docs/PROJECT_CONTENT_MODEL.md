# Project content model

Each project page requires:

- slug
- title
- project type
- current status
- evidence state
- summary
- problem
- current outcome
- technology stack
- capabilities
- relevant role lenses
- verified facts
- unknown or missing evidence
- media path
- optional subsystem evidence states

## Evidence hierarchy

1. Working public repository or personally owned source archive
2. Demo, photo, video, or deployed application
3. Original architecture diagram
4. Test results or reproducible instructions
5. Written retrospective
6. Resume claim without supporting artifact

A project can still be valuable when old artifacts are missing, but the page must
say that it is a reconstruction rather than pretending the evidence still
exists.
