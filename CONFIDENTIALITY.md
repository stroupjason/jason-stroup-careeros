# Public evidence and confidentiality policy

This repository contains only public-safe, generalized career evidence and
personally owned project artifacts.

It must never contain:

- employer source code
- internal repository names
- internal file, class, function, endpoint, collection, or service names
- customer identities
- production data or payloads
- screenshots from internal tools
- proprietary logs
- credentials or secrets
- non-public vulnerabilities
- internal architecture diagrams
- copied Jira tickets, Lattice entries, pull-request text, or manager notes
- unapproved performance metrics
- security-camera or computer-vision details for the solar trailer project that
  Jason has stated cannot currently be discussed publicly

Public case studies must use:

- generalized problem categories
- fictional or independently built examples
- transferable debugging methods
- public lab environments
- original diagrams
- original code
- personally owned project photos and video
- clearly labeled assumptions and reconstruction notes

## Role-page policy

A role page is a lens, not a credential.

Every role page must show:

- why the evidence transfers
- what remains missing
- the role's priority and maturity
- what is explicitly not claimed

Data Science must remain exploratory until rigorous modeling, evaluation, and
reproducible project evidence exists.

When uncertain, do not publish.
